# 模板来源与泛化说明

本模板于 2026-11-08 从现有 ETL 项目的 `CLAUDE.md` 提取，并对照 `doc/request-template.md`、任务 1 和任务 9 的方案文件及提交交接示例整理。来源项目位于工作区中的 `ETL作业模板/`；该路径仅用于说明来源，不是新项目的运行依赖。

本模板只是仓库级文件，未安装用户级配置或个人 Skill，也不要求新项目使用 ETL 的技术栈。

## 直接保留的规则

| 原项目规范 | 模板落点 |
|---|---|
| 统一 doc/、每个任务四文件 | AGENTS.md、task-template/ |
| spec 固定五个二级标题、短规则、固定 AC 表头 | AGENTS.md、spec.md |
| design 解释职责、数据流、关键结构、异常恢复与取舍 | design.md |
| tasks 少量可验证阶段，checklist 与 AC 一一对应 | tasks.md、checklist.md |
| 人工可复制的复核命令、真实结果与证据 | AGENTS.md、四文件模板、evidence.md |
| 计划/样本/全量结果分开；AI 检查不冒充人工复核 | AGENTS.md、checklist.md |
| 规则改变同步 AC、设计、任务与状态 | AGENTS.md、请求模板 |
| 接续前读现状，保留工作区，新增交接 | AGENTS.md、handoff.md |
| 不熟悉的功能先查资料和开源实现 | AGENTS.md 的实现规则 |
| 中文沟通、在已授权范围内连续工作 | AGENTS.md |

## 为跨项目使用作出的调整

- 将任务进度从全局规则移到 README、tasks/checklist 与交接，避免规则文件不断膨胀。
- 将 Python、PostgreSQL、Airflow、Docker Compose 等具体选择替换为项目配置项；流式处理、事务检查点等属于特定项目设计，不设为所有项目必选。
- 将正式全量运行概括为“按项目需要的真实范围验收”；纯前端、CLI 或小型库无需虚设数据全量流程。
- 保留命令可独立复制与实测要求，将固定 macOS/zsh 改成记录实际系统与 shell；当前新项目仍可选择 macOS/zsh。
- 原文件同时包含“每个 task 完成后本地存档”与“仅用户要求时提交”。模板统一为显式提交策略：默认按授权提交，用户选定每阶段提交后持续执行；推送等远端操作另按授权范围处理。
- 按本次要求明确“代码工作前先完成或更新四文件”，并增加 AC00 作为计划检查；这不等于每轮必须等用户重复确认，实施授权已存在时可继续。
- 增加 AGENTS.md 作为规则唯一来源，CLAUDE.md 作为阅读入口，避免双份规则冲突。

## 不继承的内容

不带入原项目的业务规则、数据表、样本数、性能、评分、提交标识、机器路径、任务完成状态或人工审核声明。四文件母版全部保持未执行。

## 使用边界

母版提供的是写法与流程，不是完整的具体项目方案。套用后必须填写真实需求、可判定的 AC、当前环境和实际命令，再实施验证。模板格式检查通过只能证明结构一致，不能证明业务逻辑或项目验收通过。
