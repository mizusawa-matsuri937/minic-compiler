# 可复制的工作请求

以下是提示词模板，只有实际发送给助手的请求及已有授权才界定本轮操作范围。使用前替换 `{{…}}`，不直接发送未填好的范围。

## 初始化新项目并规划首个任务

```text
请阅读 AGENTS.md、README.md 和 doc/project-config.md。
项目目标：{{目标}}。
需求与参考材料：{{路径或链接}}。
已确定的约束：{{技术栈、环境、交付物、截止时间等}}。

先检查现有项目，再填写项目配置；从 doc/task-template/ 创建 doc/task1/。
按项目规范完成 spec、design、tasks、checklist，执行 AC00 计划检查。
未知项区分工程默认与待确认事项，不照抄参考项目的完成状态。
本轮仅规划，不开始代码实现。最后说明方案、关键取舍和仍需明确的问题。
```

## 开始新任务，规划后连续实现

```text
请阅读 AGENTS.md、项目配置、README 和最新相关交接，检查当前分支与未提交修改。
本轮目标：{{需求或缺陷}}。
本轮允许的实现范围：{{任务边界、环境与操作范围}}。

创建 doc/task{{编号}}/ 的四份方案文件，先完成 spec → design → tasks → checklist，
通过 AC00 后在上述范围内连续实施和验证。关键未决选择先澄清，常规实现选择无需逐步确认。
按真实证据更新状态，执行项目配置中的 Git 策略，最后更新 README 并新增交接。
```

## 按现有方案开始实现

```text
请阅读 AGENTS.md、项目配置、README、最新相关交接和 doc/task{{编号}}/ 四份文件。
本次执行：{{T1-01 至 T1-03 等明确阶段}}。
先核对计划与当前代码是否一致；必要时更新四文件并复核 AC00，再开始代码修改。
在本轮授权范围内完成实现和必要检查，不对每一步重复请求确认。
只把有实际证据的 AC 标成通过，写清样本、集成或真实环境的验证范围。
结束时报告变更、检查结果、证据位置、未完成项，并新增交接。
```

## 调整规则或处理新增缺陷

```text
请阅读当前任务的四文件及相关实现。
需要调整/修复的内容：{{行为变化、复现输入、实际结果、期望结果}}。
本轮范围：{{仅更新方案 / 更新方案后实施修复}}。
先说明受影响的 R、AC、设计与任务，更新四文件，再按本轮范围行动。
受影响的已通过 AC 标为待重新验证；保留无关验收证据，不无理由重跑全部流程。
```

## 新会话接续

```text
请阅读 AGENTS.md、项目配置、README、doc/handoffs/ 最新相关交接和当前任务四文件。
本次继续：{{任务与阶段范围}}。
核对实际文件、Git 状态与必要的环境信息，保留现有改动。
按证据接续，不重复处理已完成的数据或工作，不把交接中的历史数字当成本轮实测。
计划缺失或过时先补齐；完成后更新状态并新增交接。
```

## 只读验收审查

```text
请按 AGENTS.md 和当前任务四文件，对 {{范围}} 做只读审查。
核对需求依据 → R → AC → 任务 → 实际证据是否闭合，检查命令、产物与状态是否一致。
可以执行已确认只读且必要的检查；会写文件或改变环境的测试先列为建议，不直接执行。
不要修改实现、提交或重跑正式流程。按影响程度报告问题，并给出具体文件/证据位置。
区分已证实问题、待验证风险和未执行检查，不把 AI 结论写成人工确认。
```

## 阶段收尾与交接

```text
请核对本轮范围内的 tasks 与 checklist，更新 README 的当前状态。
在 doc/handoffs/ 新增带日期和任务名的交接文件，记录完成项、真实证据、决策、环境、限制与下一步。
按 doc/project-config.md 的已授权策略进行本地存档，报告实际提交标识或“未提交”。
只报告本轮已完成的事项；未完成或受阻项明确说明原因。
```
